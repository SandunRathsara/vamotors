## Root cause and bounded correction

The previous correction prevented sensitive diagnostics by disabling Better Auth's logger and throwing a sanitized APIError from its router error hook. Neither the public route/shared endpoint boundary nor the server session API replaced those lost diagnostics. Synthetic actual-library SQL failures therefore produced zero events, contrary to the accepted redacted-failure requirement.

Installed Better Auth 1.6.23 has distinct paths:

- HTTP router `onAPIError`: returning void permits better-call's raw console fallback. Keep throwing a fresh sanitized APIError, but emit the fixed failure event first. Expected non-5xx APIErrors retain their existing semantics.
- Library logger: server getSession catches raw adapter errors, logs `INTERNAL_SERVER_ERROR`, and throws a safe APIError; sign-out catches deletion errors, logs, then can return200. A custom logger discards all diagnostic arguments and accepts only three exact internal failure messages. Origin/CSRF/client-denial diagnostic strings are never relayed or emitted as failure events.
- **Additional silent swallow found during correction:** `db/with-hooks.mjs` catches failed session reads in `deleteWithHooks` without logging and can return successful sign-out. An auth-only Prisma query extension emits before Better Auth can swallow any model-query failure; it rethrows the original internally, never logs it. Existing application database/transaction behavior and adapter `transaction:true` are retained.
- Public POST preflight and actual auth handler share one async-local call scope; the server getSession API has its own scope. Unexpected exceptions/5xx responses are covered at those boundaries, including Environment preflight failures. Nested scopes reuse the same state; all paths deduplicate to **one event per call**, including concurrent calls. State is not a global request/token map and requires no cleanup timer.

Event schema is exactly:

```text
console.error("AUTHENTICATION_FAILURE", {
  operation: "http" | "session" | "library",
  requestId: <server-generated random UUID>
})
```

No original error, error message, SQLSTATE, SQL, row, credential, cookie, token, URL, request path, header, or arbitrary diagnostic string enters the event. `library` is a fixed fallback for shared-options instances outside the runtime call wrappers. Correlation IDs are generated by the server, never accepted from request headers. Raw-response sanitizers and cookie lifecycle are preserved; this is failure observability, not credential-login or full feature acceptance. No telemetry dependency, exporter, infrastructure, cross-request sampling, or global rate-limit mechanism was added. Existing auth rate limiting remains unchanged; expected client denials generate no failure events.
