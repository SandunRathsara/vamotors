## F06: staging/finalization/download

initUpload(target,purpose,filename,MIME,size,sha256,category?) requires current target record read+upload/write capability, exact purpose-owner pairing and expected target revision. Target must exist (draft SaleCase created at finance initiation, BrokerageDeal at intake, ImportBatch staged first, Remittance before notice attachment). Return201 UPLOAD_READY `{uploadId,revision,putUrl,requiredHeaders,expiresAt}`; URL is bearer secret, never logs/audit/history. Browser PUT only server-selected random `env/{environmentId}/staging/{uploadId}/{nonce}`, signed expiry5min, declared MIME/hash headers; no client chosen key/path. init metadata persisted/audited first; browsers cannot write `final/` keys. CORS only exact approved authenticated app origin(s), PUT/GET/HEAD and required signed headers; no wildcard credentials or public bucket URL.

Allowed image JPEG/PNG/WebP <=2MiB each, DO/participant/vehicle/processing/notice PDF<=5MiB or supported image<=2MiB; import CSV/XLSX<=5MiB. Extension+MIME+magic bytes/actual decoder validation required; SVG/HTML/executables/polyglots and unsupported types fail422 UPLOAD_MISMATCH. filename display-only sanitized basename<=200 chars, never filesystem path; PDF size/page-count bounded50, reject password-encrypted/unreadable inputs. Server-rendered invoice PDF generated internally, not accepted as browser INVOICE purpose. Required inspection category only for INSPECTION and same deal; document participant category cannot claim another customer's attachment. Quota check init and finalization,429 QUOTA_STOP; existing downloads remain.

completeUpload(uploadId) rechecks active uploader or explicit document-finalize authority, target write/read and purpose/revision/expiry. Atomically claim INIT→FINALIZING under revision lock, release DB tx. Fetch staging once as bounded bytes, compute actual SHA256 and sniff/validate bytes/size. Avoid verify-then-copy race: **upload the exact validated bytes** to fresh server-only immutable final key (never reread potentially overwritten staging during copy); if storage supports conditional source-version copy it may be used only with equivalent tested guarantee. Reused signed staging URL cannot change validated final bytes. Verify final hash/metadata, then second short tx recheck permissions/current target revision, insert Attachment(final key/hash/size/type/owner), mark intent FINAL and audit atomically. No record links staging or unverified final. If permissions/parent revision changed during IO, linking fails403/409 and final remains unreferenced; do not “finish anyway.” Repeated finalize returns same final attachment; concurrent finalizers only one winner. Claim lease5min allows interrupted finalizer recovery using persisted attempt ID, not permanent FINALIZING. Expired original init cannot accept newly uploaded bytes; recovery of already validated claimed attempt must revalidate final hash/authority, not mint new upload capability.

Failure: object missing409 DOCUMENT_NOT_READY; declared-vs-actual mismatch422 UPLOAD_MISMATCH; expired409 UPLOAD_EXPIRED; storage transient503 STORAGE_UNAVAILABLE retryable. Uploaded bytes but DB failed leave orphan with upload/attempt correlation, not valid business evidence. Orphan reconciliation inspects DB refs and recorded final attempt hash; retries may link verified exact object, never attach another user's key. Do not automatically delete final or business documents. Staging may be removed only once capability expired and intent terminal/unreferenced with >=24h grace; staging is disposable transfer data, not retained evidence. Final unreferenced objects quarantined/monitored for operator review (no silent pruning); indefinite business retention includes failed invoice versions and replaced evidence. No automatic bucket lifecycle deletion on final prefix.

download(attachmentId) loads target, enforces current record+document field read; return DownloadDTO signed GET expiry60s, no-store, content-disposition attachment/sanitized filename. Does not expose bucket credentials/listing or raw metadata to hidden users (404). Signed URL cannot be revoked before expiry; honest security bound60s after permission removal, every new signing request revoked immediately. If stronger revocation is needed use authorized proxy, not promise impossible instant invalidation of issued bearer URL. Browser no-store/service worker exclusions required. Hash/size in DTO enable verification; record permission alone insufficient for restricted DO/private participant field.

## F14: immutable invoice/PDF lifecycle

Completion transaction creates durable PENDING InvoiceVersion request with immutable snapshot of saleRevision, customer/dealership names/identity/address, vehicle identifiers/year/mileage, sale/handover/date/method/consideration/actual receipts, declaration/template version/currency/scale and DEV notice. This is not issued document yet. Unique(completion,version), unique key and synthetic number `DEV-YYYY-000001-v1` from locked sequence; gaps after failure allowed, numbers never reassigned. A4 template with ownership, encumbrance-free and liability transfer draft declarations + both signature lines; synthetic company `VA Motors — SYNTHETIC DEVELOPMENT`, identity `DEV-NOT-LEGAL`, address `Synthetic Test Address, Sri Lanka`, no real identities. All sale categories use same snapshot system.

issueInvoice gets exact completed sale/current correction revision and own idempotency key. First/retry resumes pending snapshot; regenerate=true captures new immutable snapshot/new version even if earlier version READY. Render chosen pinned server renderer **outside tx**, bounded bytes, write unique private final object with hash, then tx recheck authority+requested saleRevision; link InvoiceVersion+Attachment and mark READY/issuedBy/time with audit. Sales changes while rendering→409 STALE_REVISION; retain failed/pending snapshot+orphan, issue new version for new revision, never label old bytes as latest corrected invoice. Storage/render failure marks FAILED with safe retry code and retains request/snapshot; response202 DOCUMENT_PENDING retryable, completed sale unchanged. Retry of SAME version must preserve snapshot/template and bytes hash; if renderer cannot reproduce bytes exactly, an unissued failed attempt can replace its unlinked object but never READY object. Reprinting READY always same retained bytes; subsequent regeneration never overwrite old key/version/number. Current invoice points newest READY requested revision, show pending correction warning until ready, never silently serve outdated revision as current.

Report PDFs use same render/private-download primitive but export snapshot is distinguished from immutable sale invoice issuance, no financial effect. Rendered export retention governed explicit retained document policy; no cross-user public download cache. PDF renderer package/version choices T03/T14 docs verification, not old CLAUDE latest prescription.

## J10: scheduled expiry and manual catch-up

POST `/api/v1/jobs/reservation-expiry` uses scheduler secret/infrastructure-authenticated invocation mapped to SYSTEM scope RESERVATION_EXPIRY; cannot call sales/refund/admin/import. Manual `runExpiry` requires current run permission, same engine. Capture server cutoff once per run; reject client future `through>now`; default now. limit1..100, stable cursor `(expiresAt,id)` for expiry and warning windows with captured cutoff. Run processes each record in independent atomic transaction; job-level partial failures explicitly listed, safe retry/catch-up, not false all-or-nothing claim. Per reservation lock current cycle/commitment+revision; due ACTIVE flags EXPIRED and status, audit, one notification event; converted/cancelled/closed skip. Due-vs-conversion: if sale wins job sees resolved and skips; if expiry wins conversion reloads revision and may proceed through expired conversion, never overwrite SOLD. Manual and cron same eventKey; no duplicated notification. User changing expected version gets409 instead of automatic stale write.

Approaching only if ACTIVE, within snapshotted lead window and before expiresAt; dedup by reservationId+policy snapshot+kind (not daily). Expired emits only expired when job late. Persist JobRun(startedAt/cutoff/finishedAt/status SUCCESS/PARTIAL/FAILED/cursor/counts/safe errors), lastSuccess/lastFailure separate; health marks stale if no successful sweep in26h. Partial sweep not lastSuccess until all cursors complete. Resume/catch-up must scan unresolved due items from earliest cutoff, not skip failures because watermark advanced. T02 wires a free supported daily schedule after Colombo midnight; actual hosted run observed T18. No requirement satisfied by “configured cron” alone. No indefinite polling/watching by this author.
