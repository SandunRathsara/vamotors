# Relational proposal and migration sequence

This is a complete proposed entity inventory, not executable migrations. T03 foundation alone authors shared schema/SQL after review; feature owners request changes, never fork schema. Every business FK `ON DELETE RESTRICT`; no cascading history loss. Archive is explicit audited action, not physical delete. Auth ephemeral sessions may expire/delete; retained business actors are not deleted. UUID PK unless noted, server UTC createdAt/updatedAt, createdBy actor FK and positive integer revision on mutable aggregates. All money follows M1, dates M3. Immutable rows have no update/delete application grant. JSON fields below have strict versioned runtime schemas, not arbitrary patches.

For any redundant vehicleId/cycleId pairs enforce composite FKs, not independent references that can disagree. Transitions/revision updates are only through guarded commands; cross-table invariants enforced by deferred constraint triggers plus transaction locks, not CHECK expressions referencing other tables. SQL enum/value checks alone do not enforce legal transitions; T03 adds transition trigger covering old/new status plus sanctioned immutable completion/import evidence. One completed sale or disposal, never both, guarded under cycle lock and deferred trigger.

Disposal approval provenance is immutable and maps exactly to api.ts ApprovalProvenance in purchase detail and DISPOSALS report/export. CURRENT requires an actual APPROVED WRITE_OFF request, separate active authorized reviewer and atomic A4 application; an imported vehicle later ordinarily written off still uses CURRENT. IMPORTED is allowed ONLY during confirmImport's scoped historical insertion, with current protected Administrator membership AND ImportBatch.import authority rechecked under auth locks. Deferred trigger requires ImportRow belongs to same batch, VEHICLES source row actually contains this disposal, ImportTargetProvenance links that row to this Disposal and cycle, batch commits in same command with initiatedBy matching current admin. No ordinary command/body may choose IMPORTED or supply bypass/reviewer fields. Status WRITTEN_OFF iff disposal evidence exists, closed cycle/unavailable/no repair or buyer commitment, and never simultaneous completion; non-WRITTEN_OFF rows with disposal fail. Positive proceeds require exactly matching DisposalReceipt on historical occurred date/method/reference; zero requires receipt absent. Missing legacy name rejects row (no invented current approval or reviewer); retain optional reference when supplied, never invent one. This is source evidence, not verification of the historical person's authority. ImportBatch/ImportRow FKs for Disposal are added and deferred constraints validated in E6 step4 before import enabled; ordinary CURRENT disposals remain possible before import tables are enabled.

## E4: cash ownership — no general ledger

Separate source-child tables share this value shape: `{id, amount>0, direction:IN|OUT, occurredDate, recordedAt, method:CASH|BANK_TRANSFER, reference?, reversalOf?, commandId, reason?, importRowId?}`. Owner FK mandatory; reversal must reference same owner and be exact opposite. Unique commandId+lineKey prevents duplicate child facts. CHECK bounds; cumulative obligation limits checked while locking source. Immutable after insert.

| Cash table / owner | Facts and projection |
| --- | --- |
| PurchasePayment → PurchaseRecord | supplier cash, settlement institution, seller cash; trade-in none |
| RepairPayment → RepairRecord | actual invoice payments (partials<=invoice, no invoice=no payment) |
| CostPayment → VehicleCost | actual payments<=incurred amount |
| SaleReceipt → SaleCase | advance/down/balance/lender receipts; REFUND outflow child tied to original reservation receipt; conversion never copies advance |
| DisposalReceipt → Disposal | actual positive proceeds once |
| FacilityPayment → CashFacility | net payout OUT; separately paid dealership deduction OUT; principal recovery IN capped by net; fee receipt IN only if separately actually paid; withheld fee/deduction not additional cash |
| BrokerageFeeReceipt → BrokerageDeal | actual processing/additional fee receipts only, never implied by setting fee |
| RECEIVED Remittance (and RemittanceReturn child) | bank commission receipt IN once; STAGED/allocations/notice/expectation are NOT cash |

Read-only `CashMovement` UNION ALL view returns stable `{sourceType,sourceId,paymentId,date,direction,amount,method}` across these sources. No writable CashFlowEntry/MoneyMovement/general-journal table or double-entry rewrite. Deductions WITHHELD by lender are informational, not dealership cash; PAID_BY_DEALERSHIP records separate outflow and cannot also subtract from net as withheld. Cash facility recoverable is actual dealership-funded net, not invented gross disbursement; separately funded charges have explicit separate recovery component if agreed, never silently added to principal.

### E5X: complete export snapshot without long serverless transactions

ExportJob(ownerUserId,filter JSON/hash,format,authzFingerprint,cutoffSequence,snapshotAt,state SNAPSHOTTING/RENDERING/READY/PAUSED_QUOTA/FAILED,serverKeysetCursor,rowCount/totals/digest,renderedRows,revision); ExportRowSnapshot(exportId,ordinal,rowKey,projectedPayload) unique(exportId,ordinal), unique(exportId,rowKey); ExportPart(exportId,ordinal,firstRow,lastRow,hash,size,attachmentId) immutable unique per export/ordinal; final manifest immutable and complete only at exact coverage. Attachments add typed ExportJob target FK/exactly-one target check, purpose REPORT_EXPORT. No public bytes, no snapshots in browser cache.

Stable source basis: BusinessSequence singleton allocated under lock by each business mutation and its CommandReceipt in same tx, monotone integer; hold guard through commit so cutoff names a COMPLETE committed prefix, not an ID potentially allocated by still-uncommitted transaction. `EntityReadVersion(entityType,entityId,sequence,revision,payload,tombstone=false)` immutable unique(entityType,entityId,sequence) stores reportable base fields after each create/edit/archive/status change; source payments/allocations append once with same sequence and are read at <=cutoff. It is domain revision evidence/read support, not independently editable totals or another cash ledger. Row payloads protected like source records; indexed(entityType,entityId,sequence DESC), sequence. Every report join selects latest base version <=cutoff and immutable payment facts <=cutoff; authoritative definitions M2/W15 unchanged. Includes party/identity descriptive fields so renaming/moving a filter match cannot mutate old export. Version writes are essential caller-tx writes (failure rolls back), seeded/imported initial versions also supplied. Epoch before E5X backfill is not exportable; serialize migration/backfill and expose feature only after complete baseline. No snapshot uses live mutable rows across invocations. `ponytail:` global business-sequence lock intentionally serializes small-dealership commits; if measured contention requires change, replace with proven complete-prefix publication mechanism, never unsafe wall-clock/id high-water approximation.

Job cutoff selected under same guard, then release; rows/parts generated in bounded independently committed progress steps (not partial business imports). Temporal prefix/version retention enables crash/retry after arbitrary pause; newer source changes cannot change original membership/values/totals. Current permission revocation invalidates whole job rather than shrinking its original population. Storage/compute usage of all retained versions/snapshots/artifacts monitored against actual free quotas; capacity failure PAUSED_QUOTA/explicit release blocker, not population cap or pruning. Nothing asserts unlimited free storage or permits spend. This is the complete-population contract for all seven reports, including >10000 matches.

Source payment sequence is obtained through immutable commandId→CommandReceipt.businessSequence, not an independently editable timestamp; remittance uses receivedCommandId. BusinessSequence is bigint monotone bounded by B; exhaustion stops with MONEY_OVERFLOW before publication. A failed transaction publishes neither sequence receipt/version nor business effects. Snapshot progress/renderer/notification read/auth-role changes do not allocate report-business sequences unless they change reportable facts. Export rowCount/totals are null while source enumeration is incomplete; READY requires exact nonnull final count/totals/hash, no gaps/duplicates and renderedRows==rowCount. End-user part download requires parent job READY+complete; paused/failed fragments are retained for retry, not offered as completed exports.

## E6: serialized migration order / deploy requirements

1. T03 pin verified auth/Prisma/client/adapter versions and transaction-capable driver without changing Next/React. Generate auth schema in isolated disposable DB, inspect exact SQL. T02 prepares role/environment constraints, not parallel schema edits.
2. Bootstrap owner/schema `vamotors`, migration history owner `vamotors_migrator`; runtime `vamotors_runtime` and job execution role scopes. Identity/auth/roles/AdminGuard, policies, command receipts, BusinessSequence/EntityReadVersion, audit/notification first. Sequence guard is acquired before business/auth locks for all report-affecting mutations, held through commit; no sequence allocated for read-only auth projection/job progress. Version schema includes allowlisted reportable fields only, NEVER credentials/session/account material. Append-only grants/triggers before any shared business writes.
3. Directory/customer/policy versions, physical identity + purchase cycle using deferred circular FKs, cycle status triggers/constraints/indexes; costs/repairs/basis/payments; sales/reservations/finance/completion/trade-in/disposal. Add circular sale/acquisition FK after both tables exist. Grants explicitly per table, no broad future-table write grants.
4. Approval typed payload dependencies, private file intents/attachments/invoice versions/ExportJob+parts; brokerage/rates/guarantors/events/checklists/facility/DealQuoteSelection; dispatch/commission/remittance/reconciliation; import graph/source claims/target provenance; read-only cash view and temporal reporting indexes. Nullable typed source links added only after target tables exist; exactly-one/unique constraints validated before enablement. Preserve trusted import existing links with deferred FK validation in one transaction; no business-row upsert to compensate migration/import ordering.
5. Seed deterministic synthetic two suitable admin/manager accounts plus restricted staff and exact rate fixtures, privately supplied passwords; no hardcoded public passwords. Real-DB rollback/revocation/race/append-only tests, then T02 authorized serialized migration deploy. No migrations in request/build/preview startup.

Indexes beyond keys: cycles(status,available,purchaseDate,id), reservations(status,expiresAt,id), repairs(vendorId,returnedDate,sentDate,id), sales(customerId,saleDate,id), source payment(occurredDate,id), deals(companyId,state,id), entitlements(companyId,state,sentDate,id), allocations(remittanceId,entitlementId), import hashes/source keys. Review EXPLAIN under representative synthetic data in lane, not speculative cache infra. All partial indexes/deferred triggers require checked-in SQL migrations; Prisma schema alone is insufficient evidence.
